01Ce que l’agent peut faire

10 outils, identiques en WebMCP et dans window.BinksyAPI (une seule table de définitions, schémas JSON lisibles avec BinksyAPI.describe()).

Outil WebMCP Méthode BinksyAPI Rôle
mockup_describe describe Décrit Mockup (Binks Design) et la liste de ses outils (schémas JSON).
mockup_etat getState État courant : photo, profondeur (source ai/quick/custom, en cours), calques logo (matière, position, réglages), matières disponibles, historique.
mockup_importer importer Importe les fichiers de l’utilisateur comme un dépôt : photo (JPG/PNG/WEBP), logos (PNG/SVG/WEBP, centrés), carte de profondeur, ou projet .mockup.json. Sans as : .json = projet, 1re image = photo si aucune, sinon logo.
mockup_profondeur depth Carte de profondeur : attendre la fin du calcul IA, relancer l’IA, ou passer en estimation rapide ; règle aussi lissage (smooth) et intensité (gain), 0 à 1.
mockup_choisir_matiere setMaterial Applique une matière au calque logo : tissu (Tissu), carton (Carton), vitre (Vitre), metal (Métal), papier (Papier), plastique (Plastique), broderie (Broderie), verre (Verre), canette (Canette), ceramique (Céramique), cuir (Cuir), bois (Bois gravé), neon (Néon).
mockup_regler_calque setLayer Règle un calque logo : réglages de matière (0 à 1 ; relief −1 à 1 ; blend 0/1/2 ; recolor + ink #RRGGBB seulement si l’utilisateur le demande), position en pixels de la photo (cx, cy, width, rotation en degrés), forme plan/cyl, visibilité, nom, épouser la surface.
mockup_calque layer Sélectionne ou supprime un calque logo (suppression : confirm: true après accord de l’utilisateur).
mockup_historique history Annule (undo) ou rétablit (redo) la dernière modification.
mockup_exporter exporter Exporte sans téléchargement forcé : rendu pleine résolution png ou jpg, carte de profondeur (depth) ou projet (json). Renvoie { files: [{ name, type, dataBase64 }] }.
mockup_reset reset Efface tout le travail (photo, logos, réglages, sauvegarde automatique) et recharge la page. Demande confirmation à l’utilisateur, puis passe confirm: true.

02Connexion A — agent intégré au navigateur (WebMCP)

WebMCP est une proposition de standard du W3C, encore expérimentale : à ce jour (novembre 2026), Chrome la propose en préversion (Chrome 146 ou plus récent, drapeau chrome://flags/#enable-webmcp-testing à activer puis redémarrer le navigateur ; essai d’origine à partir de Chrome 149). Les noms et l’emplacement des réglages peuvent changer : vérifie la documentation Chrome for Developers.

  1. Ouvre https://mockup.binksdesign.com/app.html dans ce navigateur (https ou localhost).
  2. L’app enregistre ses outils toute seule (document.modelContext.registerTool, ou navigator.modelContext sur les premières versions) : l’agent du navigateur, ou une extension comme « WebMCP – Model Context Tool Inspector », les voit apparaître.
  3. Demande ton travail à l’agent en langage naturel ; il appelle les outils ci-dessus.

Si WebMCP n’est pas disponible, rien ne change pour toi : l’app fonctionne normalement et window.BinksyAPI reste là pour la connexion B.

03Connexion B — Claude Code, Codex, Hermes, OpenCode (Playwright MCP)

Ces agents tournent sur ton ordinateur : donne-leur un navigateur avec le serveur MCP standard Playwright MCP (npx @playwright/mcp@latest). Ajoute-le à la configuration MCP de ton agent (fichier .mcp.json de Claude Code, configuration MCP de Codex, d’OpenCode ou d’Hermes ; la forme exacte du fichier dépend de l’agent) :

{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}

L’app a besoin de WebGL2. Sur un ordinateur avec carte graphique, rien à faire. Sans carte graphique (serveur, navigateur sans affichage), donne à Chromium un rendu logiciel : arguments de lancement --use-angle=swiftshader --enable-unsafe-swiftshader, à passer par le fichier de configuration de Playwright MCP (--config, rubrique browser.launchOptions.args ; voir sa documentation). Le rendu est alors plus lent.

Consigne : l’agent ouvre l’URL de l’app, attend window.BinksyAPI, puis appelle les méthodes avec l’outil d’évaluation JavaScript de Playwright MCP (browser_evaluate). Les fichiers de l’utilisateur passent en base64 ; les exports reviennent en base64.

// 1. découvrir les outils
await BinksyAPI.ready();
const info = await BinksyAPI.describe();   // { app, version, apiVersion: "1", tools: [...] }
const etat = await BinksyAPI.getState();

// 2. importer les fichiers fournis par l’utilisateur
// photo puis logo FOURNIS par l’utilisateur (base64 ou data: URL)
await BinksyAPI.importer({ files: [{ name: 'photo-client.jpg', type: 'image/jpeg', dataBase64: PHOTO_B64 }] });
await BinksyAPI.depth({ action: 'attendre', timeoutMs: 300000 });  // IA locale, ou estimation rapide
await BinksyAPI.importer({ files: [{ name: 'logo.svg', type: 'image/svg+xml', text: SVG_TEXT }], preset: 'tissu' });
await BinksyAPI.setLayer({ reglages: { flou: 0, opacity: 0.95 }, position: { cx: 820, cy: 640, width: 420, rotation: -4 } });

// 3. exporter (rien n’est téléchargé de force)
const { files } = await BinksyAPI.exporter({ format: 'png' });   // rendu pleine résolution
const projet = await BinksyAPI.exporter({ format: 'json' });          // projet .mockup.json

04Prompt prêt à copier

Ouvre https://mockup.binksdesign.com/app.html dans Chromium (Playwright MCP, avec --use-angle=swiftshader --enable-unsafe-swiftshader si pas de GPU). Attends window.BinksyAPI, appelle await BinksyAPI.describe(), puis importe ma photo et mon logo (fichiers joints, en base64) avec BinksyAPI.importer, attends la profondeur (BinksyAPI.depth), choisis la matière « tissu », place le logo sur la poitrine et exporte un PNG pleine résolution avec BinksyAPI.exporter. N’utilise jamais le logo de démo AVORA, ne redessine pas mon logo, ne demande aucune clé.

05Rien ne quitte ton navigateur

Pas de compte, pas de clé API, pas de serveur Binks Design : l’API et les outils WebMCP s’exécutent dans la page, comme l’interface. Tes fichiers restent dans ce navigateur (sauvegarde automatique IndexedDB). L’agent ne lit ni n’écrit aucune clé API.
